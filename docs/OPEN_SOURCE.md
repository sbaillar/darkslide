# Open-sourcing Darkslide: readiness audit and plan

Audited 2026-10-10 against `main` at b7eca99 (542 commits on all refs, 110 branches). This is a checklist, not legal advice. Items marked **(legal)** need an owner decision, and ideally a lawyer, before launch.

Each item has its evidence and a concrete fix. There are two kinds of blocker:
- **B-repo** must be fixed before the repository goes public.
- **B-release** must be fixed before the first public binary (a signed `.app` or DMG). Publishing source alone does not redistribute any model weights or compiled third-party code. A binary does.

`docs/THIRD_PARTY_INVENTORY.tsv` lists the 207 crates linked into the app, with their licences.

## Recommended licence: Apache-2.0

| | Apache-2.0 (**recommended**) | MIT | MPL-2.0 | GPL-3.0 |
|---|---|---|---|---|
| Linking the LGPL-2.1 `rawler` statically | OK. The public source plus `scripts/build-app.sh` let anyone relink with a modified rawler (LGPL-2.1 §6a) | OK, the same way | OK, the same way | OK: LGPL-2.1 code can be combined into GPL-3.0 |
| Mac App Store | No barrier from the licence itself. rawler's LGPL is the barrier (see B6) | Same | Same (Firefox for iOS is MPL) | Incompatible. The FSF treats App Store terms as extra restrictions; VLC was pulled for this reason |
| Plug-ins | Any licence | Any licence | Any licence; only edits to MPL files must stay open | In-process plug-ins arguably must be GPL; out-of-process plug-ins are a grey area |
| Patent grant from contributors | Yes, with retaliation | No | Yes | Yes |
| Fit with the dependencies | Matches the Rust ecosystem: 190 of the 207 crates offer MIT or Apache-2.0 | Same | Same | Same |
| Can forks become closed source? | Yes | Yes | Edits to Darkslide's files must stay open | No |

**Why Apache-2.0:**
- It is permissive with an explicit patent grant, which matters for an image-processing codebase.
- It is the norm for Rust and Swift.
- It puts no burden on plug-in authors.
- It keeps App Store distribution possible if rawler is ever replaced.
- Its NOTICE mechanism suits an app that already has to carry attributions.

**When another licence fits better:**
- Choose **MPL-2.0** if you want changes to Darkslide's own files to stay open while plug-ins and embedding stay free.
- Choose **GPL-3.0** only if you would rather prevent closed forks than keep the App Store or proprietary plug-ins available.

For contributions, use the **DCO** (a `Signed-off-by` line, checked in CI) rather than a CLA. It is lightweight, and inbound = outbound under Apache-2.0.

### B6. rawler is LGPL-2.1, linked statically (B-release; decides App Store distribution, legal)
- **Evidence:**
  - `crates/ds-raw/Cargo.toml:16` `rawler = "0.8.0"`, licence `LGPL-2.1` (upstream `rawler/Cargo.toml`, without "or later").
  - It ends up in `libds_ffi.a`, which links into the single app binary.
- **What LGPL-2.1 requires for a binary:**
  - Give recipients the licence text and rawler's source.
  - Let them relink the app with a modified rawler (§6). An app whose complete source is public and rebuilds with `scripts/build-app.sh` meets §6(a).
  - Add no terms that forbid the reverse-engineering needed to debug that (§6). The Apache-2.0 licence adds none.
- **App Store:**
  - The App Store's usage rules (device limits, no redistribution) are widely read as conflicting with LGPL §10's "no further restrictions", and users cannot relink a signed, sandboxed store build.
  - Darkslide is also not sandboxed (PLAN D9), and the App Store requires that.
  - Ship through **Developer ID and notarisation only**.
  - If the App Store becomes a goal, either replace rawler (for example with a permissive decoder plus the existing Sony ARW fast paths in `ds-raw`), or get a written exception from the dnglab authors.
- **Status (native decoders, [RAWDEC.md](RAWDEC.md)):**
  - `ds-raw` now decodes DNG, Sony ARW (uncompressed, cRAW, lossless), Canon CR2, Nikon NEF (14-bit lossless) and Pentax PEF with its own Apache-2.0 code, written clean-room from public specifications and the corpus files, and matching rawler's sensor data on the corpus.
  - Darkslide.app links no LGPL code. rawler runs in the separate, optional RAW helper (`darkslide-rawler`, `crates/ds-rawler`), a program the user downloads from Settings ▸ RAW (a GitHub release asset whose SHA-256 the app pins) and Darkslide runs as a child process over a documented protocol (`ds_raw::helper`). The helper is distributed under the LGPL's terms, with its source and relinking instructions (`crates/ds-rawler/README.md`). The `rawler` cargo feature (off by default) remains for the helper itself, tests and benchmarks.
  - Through the helper: ORF, RW2, RAF, CR3 decoding, metadata of those containers, the DNG writer (HDR/panorama output), and the colour matrices of non-DNG cameras.
  - Open owner decision: where colour matrices for non-DNG cameras may legally come from (RAWDEC.md, "Camera data"). Until then Darkslide without the helper develops DNGs (and the K-3 Mark III PEF) only.
- **Fix:**
  - State the above in `NOTICE`.
  - Ship rawler's licence in the app (B7).
  - Add a "Relinking rawler" section to `CONTRIBUTING.md` explaining that a `[patch.crates-io] rawler = { path = … }` rebuild is enough.

### B7. The app carries almost none of the notices its dependencies require (B-release)
- **Evidence:**
  - `app/Resources/Acknowledgements.md` covers the five models and Little CMS only.
  - The binary links 207 crates (`docs/THIRD_PARTY_INVENTORY.tsv`). The MIT, BSD, ISC, Zlib and Apache licences require their notices to ship with binaries.
  - Specific gaps:
    - IJG (`mozjpeg`, `mozjpeg-sys`) requires the sentence "this software is based in part on the work of the Independent JPEG Group";
    - libjpeg-turbo's BSD and zlib notices;
    - rawler's LGPL-2.1 text;
    - UniFFI's MPL-2.0 (`uniffi*`, 6 crates; its Swift templates are compiled into the app);
    - SQLite (public domain; no notice needed, but a credit is customary);
    - Unicode-3.0 (`unicode-ident`);
    - the lensfun database, which is CC BY-SA 3.0 and compiled in by `crates/ds-pipeline/src/lens.rs:14` (`include_str!`). It is included unchanged, which makes the app a "Collection" under CC BY-SA 3.0, so ShareAlike stays with the XML file. Attribution and the licence URI are still required.
- **Fix:**
  - Generate `THIRD_PARTY_LICENSES.html` (or `.md`) with `cargo about generate` from an `about.toml` that accepts only the licences in the inventory.
  - Add the model and lensfun sections from `Acknowledgements.md`.
  - Bundle it in `Contents/Resources/` from `scripts/build-app.sh`.
  - Add `cargo deny check licenses` to CI so that a new GPL or unknown licence fails the build. Allow: MIT, Apache-2.0, Apache-2.0 WITH LLVM-exception, BSD-2/3-Clause, ISC, Zlib, 0BSD, CC0-1.0, MIT-0, Unicode-3.0, Unlicense, IJG, MPL-2.0. Allow LGPL-2.1 for `rawler` only.
  - `r-efi` offers LGPL as one option, but it is not linked on macOS, and the deny config should choose MIT for it.

### B8. Model training-data terms vs. a public app (B-release, legal)
- **Evidence:**
  - `app/Resources/Acknowledgements.md:248,289,296` each say "**This model is used for personal, non-commercial use.**" That stops being true once anyone else downloads the app.
  - The weights themselves are permissively licensed:
    - Real-ESRGAN: BSD-3-Clause (`scripts/upscale-model/LICENSE-Real-ESRGAN`);
    - LaMa: Apache-2.0;
    - BiSeNet face parsing: MIT;
    - NAFNet: MIT (`scripts/denoise-model/LICENSE-NAFNet`).
  - Their **training data** is research or non-commercial only: DIV2K, Flickr2K and OST (Real-ESRGAN), Places365 (LaMa), and CelebAMask-HQ (face parsing, which is also face imagery). Whether dataset terms bind weights is legally unsettled.
  - NAFNet-SIDD's dataset (SIDD) also needs its terms checked, and its weights come from a third-party Hugging Face mirror (`huggingface.co/mikestealth/nafnet-models`, `docs/DENOISE_MODEL.md` table), not from megvii-research.
- **What the bundle contains:**
  - Bundled in the `.app`: NAFNet and Real-ESRGAN (`scripts/build-app.sh` → `Contents/Resources/Models/`).
  - Downloaded on first use from upstream Hugging Face repos, so Darkslide does not redistribute them:
    - LaMa (`app/Sources/DarkslideCore/AI/Models/DownloadableModel.swift:40`);
    - face parsing (`:65`);
    - Depth Anything V2 Small, Apache-2.0 (`:83`);
    - DETR sky, Apache-2.0 (`AI/Segmentation/SkySegmentation.swift:38`);
    - MobileCLIP-S2, Apple Sample Code License `apple-ascl` (`AI/Search/ClipModel.swift:36`).
- **Fix:**
  1. Make the **public binary** non-bundling: download Real-ESRGAN on first use from its upstream GitHub release (the URL and SHA are already pinned in `scripts/upscale-model/convert.py`), the same way LaMa is downloaded. The model has to be converted to Core ML at download time or published as a converted package. A converted package is itself a redistribution, so prefer one published by an upstream or third party, as LaMa and face parsing already are.
  2. Keep NAFNet bundled only after confirming SIDD's terms and verifying the mirror's SHA against the official megvii release. If SIDD is non-commercial, treat NAFNet like Real-ESRGAN.
  3. Rewrite the three "personal, non-commercial" lines to: "Darkslide is free, non-commercial software. This model's training data is licensed for non-commercial research; it is downloaded from <upstream> on first use, and you are responsible for your use of it." Show the same sentence once in the download prompt.
  4. Over time, replace the face-parsing model with Apple Vision person segmentation where it is good enough.
